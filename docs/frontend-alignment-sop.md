# Demo 前端体验对齐 SOP

以仓库内的 MIT 开源 `deepseek-chat-demo` 为实现基础，以 DeepSeek 官网的可观察交互为参考。本轮先完成已走查的输入区、左侧会话栏与搜索来源体验。站点沿用自身标识和样式。新的体验差异继续记录到走查文档，再排入对应阶段。[开源许可证](../web/LICENSE) · [前端体验走查记录](frontend-experience-review.md)

「行业分析师」按钮列为第一项，须从新对话和已有会话的输入区移除。Skill 的入口和呈现方式等本轮官网交互对齐验收完成后再讨论。既有会话的 Skill 配置和服务端行为沿用现有规则。[产品需求](PDR.md) · [开发计划](PDP.md)

## 1. 记录基线

在相同视口、缩放比例和主题下，对照用户提供的官网与 Demo 截图。静态截图用于确认可见入口和信息层级，动效以同一操作的录屏为准。优先记录左侧栏开合、收起时发起会话搜索、点击网页数量打开右侧面板这三条路径。记录操作起点、结束状态及当时的站点版本或日期。截图里看不出的搜索匹配范围，在官网可用时用自建会话实测标题命中与正文命中，结果写入走查记录。

在 Demo 准备新对话、已有会话、可搜索的历史会话，以及含多个来源的历史回复。准备站点元数据完整、缺失、图标加载失败三类可重复使用的搜索结果样本。后续用固定样本验收界面，用真实 Firecrawl 请求验证接入。

## 3. Firecrawl 搜索结果的验收口径

官网用于核对网页数量入口、面板开合、列表进入顺序、卡片信息层级与打开原文的操作。Demo 的来源由 Firecrawl 提供。检索到的网站、条数、排序、摘要和可用元数据按 Demo 实际返回与现有聚合规则验收，允许与官网不同，因此卡片内容和个别字段的显示也会不同。

| 字段或状态 | 展示规则 |
| --- | --- |
| 网页数量 | 按当前回复实际可打开的来源列表展示。 |
| 网站名称 | 优先展示可验证的站点名称，字段缺失时显示来源域名。 |
| 站点图标 | 有可用图标时显示站点图标，缺失或加载失败时使用现有通用链接图标。同一来源在提示和卡片里使用同一规则。 |
| 文章与日期 | 展示实际文章标题和可用摘要。日期有可靠值时显示，缺失时省略。 |
| 无结果、失败或额度耗尽 | 复用当前搜索状态提示，普通对话和已产出的内容仍可使用。 |

当前 Worker 发给前端的网页结果只有链接、文章标题和摘要，前端已能读取可选的站点名称和图标。先核对实际 Firecrawl MCP 响应。若有可靠字段，将其作为可选字段贯通 Worker 与前端，并验证旧记录可继续按域名和通用图标展示。若字段不可用，保留上述兜底，并把额外元数据来源作为独立待决项。 [Firecrawl 结果归一化](../worker/src/firecrawl.js#L191) · [流式事件](../worker/src/chat-loop.js#L131) · [前端来源映射](../web/src/services/chat/view.ts#L118)

## 4. 联调、发布与回退

1. 每阶段从 `web/` 执行 `pnpm type`、`pnpm lint`、`pnpm build`。如改动 Worker 搜索响应，按现有变更流程补查 Worker 语法与流式协议兼容性。 [项目脚本](../web/package.json) · [变更 SOP](change-sop.md)
2. 在测试环境逐项回放 FE-01 至 FE-06，记录环境、操作、预期、实际、截图或录屏。补查窄屏布局、键盘操作、减少动态效果、历史会话恢复，以及无搜索的普通对话。用真实 Firecrawl 请求走通网页数量入口、引用、来源面板和原文链接。
3. 已走查项目都通过，且 Firecrawl 数据差异有样本说明时，记录候选版本和验收结论，供发布确认。发布后重验普通对话、会话搜索和打开来源。若出现会话打不开、来源与引用错配或普通对话回归，按相关阶段回退到上一可用构建或部署版本，再用原验收路径复测。
4. 本轮收口后，再讨论 Skill 入口。若走查中发现其他官网交互差异，补充复现证据和验收标准后纳入下一次评审。

## 5. 桌面侧栏动效调整计划

2026-11-19 在已登录的 DeepSeek 官网 Chromium 桌面视口中，通过 Web Animations API 读取运行时参数，并逐帧采样面板宽度。右侧面板使用 `100ms ease-out`、零延迟展开，一次复测约在点击后 111ms 到达完整宽度。该回复的 14 个来源在第一帧已挂载，前三张卡片未测到独立淡入或位移。左侧栏展开和收起均为 `300ms cubic-bezier(0.4, 0, 0.2, 1)`，侧栏内容同步横移、淡入淡出，主区标题留白同步过渡。收起态快捷按钮组的显隐过渡为 `200ms`，使用同一缓动曲线。以上参数来自桌面端实测。

1. **右侧搜索结果。** 先将桌面展开从 `240ms` 改为 `100ms ease-out`，移除桌面卡片首帧等待和逐张延迟，让全部来源随面板展开显示。以 1、5 和 14 条来源分别验收，检查首帧来源已挂载、面板约在 100ms 完成过渡，且卡片数量增加时不会拉长入场。复测动画中关闭、重开和切换回复，并检查引用、原文链接与图标兜底。窄屏动效留待移动端基线实测。 [搜索面板](../web/src/components/search/SearchPanel.tsx) · [搜索面板样式](../web/src/components/search/SearchPanel.module.css)
2. **左侧会话栏。** 将桌面占位宽度、侧栏内容横移和透明度，以及对话标题留白统一为 `300ms` 和实测曲线。收起态的展开、新对话、搜索按钮以 `200ms` 交接。两组控件淡入淡出时只允许当前组接受焦点和点击。验收双向过渡、快速反向开合、键盘焦点交接，以及展开态和收起态的会话搜索、会话切换和草稿恢复。沿用 Demo 的样式和会话搜索规则。 [主布局样式](../web/src/app/App.module.css) · [侧栏样式](../web/src/components/sider/Sider.module.css) · [会话头部样式](../web/src/components/session/SessionView.module.css)

最后在相同桌面视口逐帧对照两侧动效，复测开启「减少动态效果」后直接到达最终状态，并对现有移动端交互做回归检查。完成浏览器验收后运行类型检查、Lint 和生产构建。Firecrawl 来源内容继续按第 3 节验收。
