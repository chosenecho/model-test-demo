# model-test-demo 产品开发计划（PDP）

版本 v0.3 · 开发讨论稿 · 依据 PDR v0.5。[产品需求文档](PDR.md)

首版完成两条用户链路。用户可在普通对话中开启「智能搜索」，看到 Firecrawl MCP 的调用状态，并收到带可追溯来源的回答。用户也可独立启用唯一预设 Skill「行业分析师」，刷新后恢复会话设置，下一条消息使用服务端注入的分析指令。

继续使用 DeepSeek chat-demo、Cloudflare Workers Static Assets、Cloudflare Workers 和 D1。沿用邀请码登录、固定 DeepSeek 模型、本地优先的会话及附件链路。当前对话接口只转发一次模型请求，Worker 工具循环和服务端提示词组装是本次主要开发项。[对话入口](../worker/src/index.js#L655) · [会话同步](../web/src/services/chat/sync.ts) · [部署配置](../worker/wrangler.toml)

## 2. 开发任务

### 兼容性验证

- 使用当前固定 DeepSeek 模型及消息接口，验证自定义工具声明能产生 `tool_use`，Worker 回填对应的 `tool_result` 后能获得最终回复。记录流式参数片段的组装方式、续轮所需的消息块以及每轮用量事件。
- 从测试 Worker 连接真实 Firecrawl MCP，确认可用的传输方式、鉴权位置、搜索工具名及输入输出格式。保存脱敏样例，供联调和测试复用。记录工具轮次、单次与整轮超时、结果大小的建议值，依据实测确定配置。
- 固定模型、接口或 Worker 运行时出现兼容问题时，记录复现条件并先解决对应依赖。固定模型调整需同步确认 PDR 的首版约束。

### Skill 与系统提示词

- 前端支持用户查看「行业分析师」的简介和当前启用状态，并为新建对话和已有会话启用或关闭该 Skill。桌面与移动端均可操作，具体入口待交互方案确定。沿用会话设置的本地保存与同步路径，新会话和旧会话缺少该设置时按关闭处理。下一次发送读取最新设置，生成中的请求使用发起时的设置快照。[对话状态](../web/src/services/chat/store.ts) · [会话同步](../web/src/services/chat/sync.ts)
- Worker 校验 Skill 和搜索开关，缺省按关闭处理，非法值给出明确错误。所有对话请求由 Worker 组装基础系统提示词和工具声明，启用 Skill 时追加项目方维护的对应版本指令。客户端传入的 `system`、`tools`、`tool_choice` 与应用自己的开关字段在上游请求组装时剔除。[现有请求校验](../worker/src/index.js#L771)
- Worker 随回复返回实际使用的 Skill 版本，前端随该条回复保存并同步。确认允许同步的消息结构可保留版本字段。用户消息、工具结果与系统提示词继续按各自角色传递。

### 搜索、额度与用量

- Worker 仅在「智能搜索」开启且用户具备权限时声明 Firecrawl 搜索工具。模型请求的工具名与参数经服务端校验后，由 Worker 调用已登记的 MCP 服务。工具结果按调用 ID 回填。智能搜索统一走这条链路，避免继续走上游托管搜索绕开 Firecrawl 额度。
- Worker 通过 SSE 向现有聊天界面传递「执行中」「完成」「失败」和可展示的来源。引用可追溯到本轮搜索结果。零结果、服务失败或额度耗尽时，向界面明确反馈，模型依据已有信息继续回答。用户停止时保留已生成正文，停止发起后续模型和工具请求，并尽力取消进行中的请求。
- `FIRECRAWL_API_KEY` 由项目方配置为 Worker Secret，仅用于 Worker 与 Firecrawl MCP 服务之间的鉴权。模型只接收工具用途、参数定义和经过筛选的结果。浏览器响应、模型请求及日志均排除密钥、含鉴权信息的地址与请求头。搜索结果按外部资料处理，保留必要的标题、链接和摘要。
- **每位用户每天 200 次 Firecrawl 搜索调用。** 日期按 `Asia/Hong_Kong` 计算，香港时间零点进入新日期。在 D1 按用户做日计数，用原子条件写入预占额度。获得名额后才发起调用，并在出站前检查日期归属。实际发出的失败、超时和重试各占一次。只有确认请求未发出时才释放预占。达到上限时显示「今日搜索额度已用完」，普通对话继续可用。其他用户的用量不影响该额度。
- 搜索次数与现有模型额度分别记账。同一条用户消息沿用一个请求 ID，按轮记录上游模型的实际用量并汇总结算一次。确定续轮的额度预占或追加预占策略。对重复请求、取消和部分失败验证结算幂等，对缺失的上游用量沿用待对账处理。[现有模型额度实现](../worker/src/core.js#L310) · [模型额度验收](quota-sop.md#14-上线验收5-步)

### 历史会话搜索

- 复用会话摘要、详情缓存和 IndexedDB 读取路径。先实现标题、提问和回答的关键词匹配，再接入现有弹窗的高亮摘要、搜索中、空结果和读取失败状态。[会话搜索组件](../web/src/components/sider/SessionSearch.tsx) · [本地会话存储](../web/src/services/chat/db.ts)
- 为正文结果携带会话 ID 和消息 ID。打开会话并等待消息渲染后，在消息列表内滚动定位。处理旧查询晚返回、目标消息失效以及自动滚动到底部覆盖定位的问题。[对话状态](../web/src/services/chat/store.ts) · [消息列表](../web/src/components/messages/MessageList.tsx)
- 用浏览器固定样本验证未预先打开的旧会话、多条正文命中、会话切换、键盘操作和移动抽屉。通过类型检查、Lint 和生产构建后，按常规静态资源发布流程上线。[历史会话搜索 SOP](session-search-sop.md)

### 历史会话搜索界面对齐

先复拍当前 Demo 建立差异清单，再依次处理空框与窄屏布局、结果和反馈、键盘选择与跳转、过渡动效。前端按官网已采集的状态复现操作路径与信息层级，使用 Demo 自有视觉样式。测试按同视口、同主题、同状态配对复拍，交付前后截图和开关、展开、收回的录屏。缺少官网证据的状态登记补采条件。验收同时覆盖本地历史检索和普通对话回归。[UI 走查](frontend-experience-review.md#fe-07-会话搜索弹窗对照) · [界面对齐 SOP](session-search-ui-alignment-sop.md)

## 3. 验收清单

先用模拟模型和 MCP 验证工具事件、失败、停止和并发，再在测试环境使用固定模型与真实 Firecrawl 走完整链路。端到端结果用请求 ID 串联页面、Worker 事件和用量记录。

- [ ] **对话回归** 邀请码登录后完成多轮对话，回复逐步显示，刷新后恢复历史。验证附件使用、停止生成及网络错误后的重试。
- [ ] **历史会话搜索** 用仅出现在标题、用户提问和助手回答中的关键词分别验证。正文结果显示高亮片段并定位到视口内的原消息。复测旧会话、快速改词、取消后恢复焦点、草稿保留，以及移动端选中结果后关闭抽屉。
- [ ] **历史会话搜索界面对齐**。桌面、窄屏和深色状态均有配对截图。录屏覆盖打开、展开、收回和关闭。上下键选中、Enter 跳转、Escape 恢复焦点和减少动态效果通过。记录未验证状态与补采条件。
- [ ] **Skill** 新会话和没有开关记录的旧会话默认关闭。打开后刷新仍开启，下一次模型请求追加分析指令，回复记录实际版本。再次关闭后，下次请求使用基础提示词。非法开关返回明确错误。核对发送给模型的提示词和工具声明由 Worker 组装。
- [ ] **真实搜索** 保持 Skill 关闭并开启「智能搜索」，验证模型触发搜索、Worker 通过 MCP 调用 Firecrawl、结果按调用 ID 回填。界面展示工具状态，回答中的来源能在本轮结果中找到。验证只开启 Skill 时 Firecrawl 未收到调用，两项同时开启时分析指令和搜索工具均生效。
- [ ] **密钥保护** 分别覆盖成功、超时和鉴权失败，检查浏览器响应、发往模型的请求和日志，确认其中没有 API Key 或含鉴权信息的地址与请求头。
- [ ] **每日额度** 测试库把用户 A 当日计数预置为 200，用户 B 为 0。A 触发搜索只看到额度提示且能继续聊天，B 同时搜索则实际发出一次。验证失败、超时和重试计数，未发出时预占可释放，香港时间零点进入新额度日。
- [ ] **失败与停止** 模拟 MCP 失败、超时及触及工具调用限制，验证状态和降级回答。工具执行中点击停止后，保留正文，进入已停止状态，后端停止发起新调用。
- [ ] **用量与重复提交** 一条消息触发多次模型调用时，可按请求 ID 核对各次用量与总账。重复提交同一标识时，模型扣费和 Firecrawl 出站次数均维持首次提交后的记录。

## 4. 发布与回滚

1. 在本地或测试环境检查 Worker 语法、前端类型和 lint，构建静态资源，再完成回归及真实链路验收。D1 变更先用本地库验证迁移与旧会话兼容，生产迁移前备份。[前端脚本](../web/package.json#L8) · [变更 SOP](change-sop.md#1-通用规约所有改动都适用)
2. 部署前由项目方配置测试与生产各自的 Worker Secret。按现有 SOP 用功能开关控制新链路，先部署兼容代码，再向试用用户启用。记录部署版本、D1 迁移版本和验收请求 ID。[变更 SOP](change-sop.md#12-五条硬规矩)
3. 发布后检查模型与 MCP 错误、搜索日用量、重复扣费和日志脱敏。出现密钥暴露、超过额度或扣费异常时关闭受影响功能。若普通聊天受影响，恢复已验证的前一版本。保留已写入的用量和会话数据供对账。[额度排障与回滚](quota-sop.md#7-排障)
