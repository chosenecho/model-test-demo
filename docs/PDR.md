## 1. 产品目标

为受邀用户提供一个网页对话工作台。用户可以直接与模型多轮对话，也可以按需启用一个预设 Skill。回答需要外部信息时，模型可以调用项目接入的工具，包括通过 MCP（Model Context Protocol）接入的工具，并根据返回结果继续回答。

首版的网页搜索场景在普通对话中验收。用户开启「智能搜索」并提出需要查证的问题，可以看到工具执行状态，并收到引用 Firecrawl 搜索结果的回答。

## 2. 已确定的架构与项目现状

前端基于 DeepSeek 官方开源的 chat-demo，通过 Cloudflare Workers Static Assets 部署。后端使用 Cloudflare Workers，服务端数据库使用 Cloudflare D1。网页搜索由 Worker 通过 MCP 接入 Firecrawl。项目方提供的 API Key 保存在 Worker Secret `FIRECRAWL_API_KEY` 中，仅用于 Worker 向 Firecrawl MCP 服务发起请求时的鉴权。[前端项目](https://github.com/deepseek-ai/chat-demo) · [部署配置](../worker/wrangler.toml)

## 3. 首版范围

### 3.1 网页对话

沿用现有邀请码登录、固定模型和会话工作台。用户能新建会话、发送消息、接收流式回答、停止生成，并在刷新后恢复已保存的会话。网络、模型或额度错误应给出对应提示，保留用户已发送的消息和已生成的正文，方便重试。

#### 历史会话搜索

展开或收起桌面侧栏时，以及从移动端抽屉，都可以打开同一个会话搜索弹窗。用户可按关键词查找本机已保存的会话标题、用户提问和助手回答。正文结果显示会话标题和命中片段，高亮关键词。同一会话中多条消息命中时，用户可以分别打开。标题结果打开会话，正文结果打开会话并滚动到对应消息。关闭搜索后可继续原会话，草稿保留。

首版正文范围为每个会话当前选中的分支。搜索覆盖本机已保存的旧会话，无需预先打开会话或重建历史。关键词和历史正文在浏览器内处理，搜索无需调用模型或 Firecrawl。实施与验收见 [历史会话搜索 SOP](session-search-sop.md)。

### 3.2 工具调用与 MCP

Firecrawl 网页搜索是首版接入的只读 MCP 工具。用户打开「智能搜索」后，Worker 根据用户权限和会话配置向模型提供搜索工具。模型发起调用后，Worker 校验工具和参数，通过 MCP 调用 Firecrawl，并将结果关联到对应的调用后回传模型。搜索开关独立于 Skill。

每位用户每天有 200 次 Firecrawl 搜索工具调用额度，按香港时间（`Asia/Hong_Kong`）自然日计算，每天零点恢复。额度只计当前登录用户自己的调用，不因其他用户的使用而减少。Worker 在发起调用前预占额度，同一用户的并发请求共用这 200 次。每次实际发起的搜索工具调用计 1 次，超时、失败和重试均计入。确认未发起的调用释放预占额度。额度用完后，Worker 停止发起该用户的 Firecrawl 搜索调用，页面提示「今日搜索额度已用完」，普通对话仍可继续。

网页显示工具名称及「执行中」「完成」「失败」状态。工具超时或服务不可用时，页面展示失败状态，模型依据已获得的信息继续回答，并在需要时说明信息缺口。停止生成后，后端停止发起后续模型请求和工具调用，并尽力取消仍在进行的请求。

后端限制工具调用轮次、执行时长和结果大小，到达限制时结束本轮调用并说明原因。MCP 服务地址和鉴权凭证由项目方在服务端配置。Worker 向模型提供工具名称、用途和参数定义，向前端传递工具状态和展示所需的结果。发送给浏览器、模型或日志的工具信息须移除密钥及含鉴权信息的请求地址和请求头。

### 3.3 预设 Skill 与系统提示词

首版仅提供「行业分析师」一个预设 Skill，由项目方维护名称、简介和任务指令。启用后，模型按分析框架组织观点、依据和结论，并说明关键不确定性。

用户可以查看「行业分析师」的简介和当前启用状态，并为当前会话启用或关闭该 Skill。新会话默认关闭，状态按会话保存，刷新后恢复，变更从下一次发送生效。Skill 与「智能搜索」可独立启用。具体入口和布局待交互方案确定。

所有回复都由服务端注入基础系统提示词，其中包含助手定位、回答规则和通用工具使用约束。启用「行业分析师」时，服务端追加相应任务指令，并记录该回复使用的 Skill 版本。用户消息和工具结果各自保留消息角色。

## 4. 验收条件

| 场景 | 通过标准 |
| --- | --- |
| 多轮对话 | 邀请码登录后新建会话，第二轮问题能用到第一轮的信息。回答逐步显示，刷新后可重新打开该会话。 |
| 历史会话搜索 | 分别用仅出现在标题、提问、回答中的关键词搜索。标题结果打开会话，正文结果显示高亮片段并定位原消息。刷新后可搜索尚未打开的旧会话。无匹配时显示空结果，取消搜索后保留原会话与草稿。 |
| Firecrawl 搜索与 MCP 调用 | 保持 Skill 关闭，打开「智能搜索」并触发搜索。核对 Worker 通过 MCP 调用 Firecrawl 并将结果回传模型。页面显示工具状态，回复来源可追溯到本轮搜索结果。 |
| Firecrawl 密钥保护 | 分别验证调用成功和失败时的浏览器响应、发往模型的请求及日志，确认其中没有 API Key 或含鉴权信息的请求地址和请求头。 |
| Firecrawl 每日额度 | 用户 A 当日已用 200 次，用户 B 当日为 0。A 触发搜索时看到额度用完提示，仍可继续普通对话；B 同时搜索则正常发出 Firecrawl 调用。模拟 Firecrawl 超时后核对该次调用仍计数。香港时间零点后 A 可再次搜索。 |
| Skill 与系统提示词 | 新会话默认关闭「行业分析师」，上游请求使用基础系统提示词。打开开关并刷新后，会话仍为开启状态，下一次请求追加「行业分析师」指令，回复记录 Skill 版本。关闭后，下一次请求恢复为基础提示词。 |
| 配置校验 | 服务端校验 Skill 开关值。上游只收到服务端组装的系统提示词和工具声明。 |
| 工具失败与停止 | 模拟 MCP 超时，页面显示失败，已有对话可继续使用。工具执行期间点击停止，当前轮保留已收到的正文并进入已停止状态，服务端停止发起下一次调用。 |
| 用量与排查 | 一轮用户消息触发多次模型请求时，支持按同一个请求标识追踪各次调用，并汇总实际模型用量。重复提交同一个请求标识不会重复扣费。 |

## 5. 交付顺序与待定项

1. 保持网页对话基线可用，将基础系统提示词移到服务端，接通「行业分析师」开关、指令注入和版本记录。
2. 通过 MCP 接入 Firecrawl，完成服务端鉴权、每日调用额度、参数校验、结果回传和网页状态展示。
3. 验收「智能搜索」的 MCP 调用链路、密钥保护、每日额度和 Skill 指令注入，并覆盖超时、停止、配置错误和模型用量结算。

首版范围按邀请码试用、单一项目模型、一个预设 Skill 和项目方配置的 MCP 工具估算。公开注册、用户自建 Skill、自接 MCP、多模型切换和可写工具作为后续版本议题。

Firecrawl MCP 的连接配置，以及工具调用轮次、超时和结果大小的具体上限，由技术设计确定。
