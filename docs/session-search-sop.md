# 历史会话搜索实施与验收 SOP

依据 [PDR v0.5](PDR.md) 和 [PDP v0.2](PDP.md)。本次改动从侧栏放大镜进入，覆盖标题、提问和回答的搜索与定位。

## 1. 复现与基线

2026 年 11 月 19 日，在登录后的 DeepSeek 官网桌面 Chromium 中，用自建测试会话分别搜索标题、仅出现在用户提问中的短语和仅出现在助手回答中的短语。三种查询均能找到目标会话。正文结果展示会话标题和带高亮的命中片段。点击提问或回答结果，搜索弹窗关闭，目标会话打开，对应消息出现在视口内。无匹配时显示「暂无相关结果」。本次实测覆盖上述行为，未确定官网对未选中分支的检索规则及完整排序规则。[DeepSeek 官网](https://chat.deepseek.com/)

Demo 的弹窗从会话摘要中读取标题并做关键词匹配。准备一条标题为「星图记录」的已保存会话，在提问中写入「晨星样本」，在回答中写入「夜航样本」。改动前只有搜索「星图记录」能找到该会话。实施时将三个词用作固定复测样本。[搜索弹窗](../web/src/components/sider/SessionSearch.tsx#L17)

## 2. 实施步骤

1. **读取可检索历史。** 用会话摘要作为遍历入口，正文优先读取当前详情缓存，未加载的会话从 IndexedDB 读取。复用现有分支可见消息逻辑，只检索各会话当前选中分支的已保存提问和助手正文。附件原件、思考块和工具块排除在正文范围外。分批读取，扫描详情时避免填满对话详情缓存。首版使用浏览器现有数据结构，无需迁移。[历史读取示例](../web/src/services/chat/backup.ts#L19) · [本地存储](../web/src/services/chat/db.ts#L78) · [分支逻辑](../web/src/services/chat/branches.ts)
2. **生成并展示匹配。** 查询去掉首尾空白，英文按大小写不敏感的子串匹配，中文按原词匹配。空查询只显示搜索框，背景压暗并模糊。有关键词时再显示结果区。非空查询按既有会话顺序展示，正文每条命中消息展示一条结果，包含会话标题、围绕首次命中的短片段和关键词高亮。摘要按纯文本渲染。读取时显示「搜索中」，结束后再显示空结果。读取部分失败时保留可用匹配并提示重试。快速改词、关窗或替换历史后，丢弃失效查询的结果。[搜索弹窗](../web/src/components/sider/SessionSearch.tsx)
3. **打开并定位。** 标题结果沿用打开会话的行为。正文结果携带会话 ID 和消息 ID，关闭弹窗和移动端抽屉后选择会话，等待消息渲染，再在对话滚动区定位目标。定位期间协调消息列表的自动跟随，避免旧请求在用户切换会话后继续滚动。消息已删除或换到其他分支时，打开仍可用的会话并提示目标消息不再可见。会话已删除时，留在当前会话并提示结果已失效。取消搜索时恢复入口焦点。沿用现有键盘操作，输入法组合期间避免误提交。[会话选择](../web/src/services/chat/store.ts#L532) · [消息列表滚动](../web/src/components/messages/MessageList.tsx#L84)

搜索在浏览器中执行。通过网络面板核对关键词和正文未随搜索发出，并确认搜索过程未触发模型或 Firecrawl 请求。打开会话时仍走现有会话加载与同步逻辑。

## 3. 验收

先在 Chromium 用固定本地历史样本验收。准备一个刷新后尚未打开的旧会话、一个包含较长回答的会话，以及一组当前分支与旧分支内容不同的会话。样本可以用本地历史夹具构造，便于稳定重现加载和并发情况。

| 用例 | 操作与通过标准 |
| --- | --- |
| 标题和正文 | 分别搜索「星图记录」「晨星样本」「夜航样本」。标题可打开会话。两条正文结果展示正确标题和高亮片段，点击后各自的消息进入视口。 |
| 多条命中 | 在同一会话两条消息中加入相同关键词。两个正文结果可分别定位。在长对话中选择靠前的结果，消息渲染稳定后仍留在目标位置。 |
| 旧会话和分支 | 刷新后直接搜索尚未打开的旧会话，正文可命中。切换到另一分支后重新查询，结果对应当前选中分支。 |
| 查询状态 | 连续更换查询词、输入空白、搜索不存在的词，并模拟读取错误和历史替换。结果对应最新查询，清空后恢复单行搜索框，无匹配与读取失败各自有说明，过期结果不会覆盖当前列表。 |
| 桌面与移动端 | 从桌面展开态、收起态及移动端抽屉打开搜索。验证输入框聚焦、键盘选择、Escape 关闭并恢复焦点、移动端选中结果后关闭抽屉，以及取消后保留会话和草稿。 |
| 失效结果 | 在搜索后删除目标消息或会话再点击。显示对应提示，且没有意外切换会话或跳到底部。 |
| 本地处理 | 搜索时检查网络请求，确认关键词和正文未外发，无模型或 Firecrawl 调用。 |

## 4. 发布与回滚

在 `web/` 依次执行 `pnpm type`、`pnpm lint`、`pnpm build`。验收记录包含浏览器、视口、样本、操作和结果。随后按现有静态资源流程发布，记录前一版本和实际发布版本。[项目发布 SOP](sop.md)

上线后用测试会话复测标题搜索、正文高亮和消息定位，再发一条普通消息检查对话。若出现打开错会话、草稿丢失或正常对话受影响，按发布 SOP 回到上一已验证版本，并复测对应路径。历史继续由现有浏览器存储和同步机制管理。
